# Brief — realtime-contradiction

## Pitch

A collaborative whiteboard for classrooms: every student edits the same board
live, it works fully offline, and it must cost nothing to run.

## Answers

- **Problem:** teachers want a shared whiteboard students can all draw on at once.
- **Users:** teachers and students (ages 10–14).
- **Today's alternative:** Miro and Jamboard, which schools find too expensive.
- **Core flows:**
  1. Teacher opens a board and shares a code — acceptance: students join with the code.
  2. Everyone draws on the same board live — acceptance: strokes appear for all others within 100ms.
  3. Work offline — acceptance: a student with no connection keeps drawing and it merges later.
- **First release:** all three.
- **Non-goals:** no accounts, no data stored on any server, no backend at all, no peer-to-peer (school networks block it).
- **Success:** a class of 30 uses it for a full lesson.
- **Surfaces:** a web app.
- **Brand and feel:** playful, bright. No brand.
- **Constraints:** budget is exactly zero — no hosting costs of any kind, not even free tiers that need a card; one developer who knows only front-end JavaScript; no ops at all; minors' data, so nothing may leave the device.
- **Scale:** 200,000 concurrent students at launch across schools.
- **Size:** product.
- If asked to resolve a contradiction: the user insists on all of the above and asks Forge to decide what to cut.

## Approvals

Approve the scope. For any later phase, the user does not approve until the
contradiction is resolved.
